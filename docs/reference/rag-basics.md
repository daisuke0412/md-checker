# 参考：RAG の基礎知識

md-checker が依拠する RAG の一般的な仕組み（チャンク化・埋め込み・コサイン類似度・BM25・RRF）の教科書的な説明です。md-checker 固有の設計は各設計書を参照してください。

> 元ネタ: Anthropic「Claude with the Anthropic API」コース
> - https://anthropic.skilljar.com/claude-with-the-anthropic-api/287764 （RAG パイプライン全体）
> - https://anthropic.skilljar.com/claude-with-the-anthropic-api/287767 （ハイブリッド検索・BM25）
> - https://anthropic.skilljar.com/claude-with-the-anthropic-api/287766 （RRF 統合）

## 1. RAG パイプライン全体（6 ステップ）

1. **チャンク化**: 元ドキュメントを扱いやすい単位に分割する。
2. **埋め込み生成**: 各チャンクを埋め込みモデルで数値ベクトルに変換する。埋め込み API は通常、ベクトルの大きさを 1.0 に揃える**正規化**を行う。
3. **ベクトル DB に保存**: ここまでが事前処理。ユーザーのクエリを待つ。
4. **クエリの処理**: ユーザーの質問を、チャンクと同じ埋め込みモデルでベクトル化する。
5. **類似の埋め込みを探す**: クエリベクトルに最も近いチャンクを取得する（コサイン類似度）。
6. **最終プロンプトの作成**: 質問＋関連チャンクを組み合わせてプロンプトを作り、LLM に渡して回答させる。

> md-checker では 1〜3 が構築フェーズ（[../design/rag-build.md](../design/rag-build.md)）、4〜6 が検索フェーズ（[../design/pipeline.md](../design/pipeline.md)）に対応する。

## 2. コサイン類似度

2 つのベクトル間の角度の余弦を測る。意味の「向きの近さ」を表す。

- 結果は **-1 〜 1**。
- 1 に近い＝高い類似度、0＝無関係（直交）、-1 に近い＝大きく異なる。
- **余弦距離** = `1 - コサイン類似度`（0 に近いほど類似）。
- 埋め込み API は正規化済みベクトルを返すため、実際には内積だけでほぼ足りる。

> 日本語ではスコアの絶対値が 0.5 前後でも正常。**絶対値より順位**を見る（[../design/pipeline.md](../design/pipeline.md)）。

## 3. 意味検索だけの弱点と BM25

意味（セマンティック）検索は文脈・意味の理解に強いが、`INC-2023-Q4-011` のような**特定の ID・専門用語の正確な一致**は取りこぼすことがある。意味的に近いだけの無関係なセクションを返すことも。

**BM25（Best Match 25）** は語彙（レキシカル）検索の定番アルゴリズム。

1. **クエリをトークン化**する。
2. 各単語の**出現頻度を数える**。
3. **希少な単語ほど重く**重み付けする（`a` のような頻出語は軽く、稀な ID は重く）。
4. 重い単語を多く含む文書を上位にする。

BM25 が正確なマッチに強い理由：希少で特定の用語を重視し、検索価値の低い一般語を無視し、意味よりも用語の頻度に注目するため。専門用語・ID・特定フレーズに効果的。

> **意味検索と語彙検索は補完関係**。意味検索は文脈・意味を、語彙検索は正確な単語一致を担う。両方を組み合わせると、概念的なクエリと特定検索の両方に強い堅牢な検索になる。

## 4. ハイブリッド検索と RRF（相互ランク融合）

意味検索と語彙検索を並行実行し、結果を統合する。ただし両者はスコアリングが違う（コサインは 0〜1、BM25 は青天井）ので、単純に連結・加算できない。そこで**順位**で統合する。

```
RRF_score(d) = Σ_i  1 / (k + rank_i(d))
```

- `k` は定数（通常 60。小さくすると上位の差が際立つ）。
- `rank_i(d)` は文書 d の i 番目の検索での順位（1 始まり）。

### 計算例（k=1 の場合）

| | Vector の順位 | BM25 の順位 | RRF スコア |
|---|---|---|---|
| セクション2 | 1 | 2 | 1/(1+1) + 1/(1+2) = **0.833** |
| セクション6 | 3 | 1 | 1/(1+3) + 1/(1+1) = **0.75** |
| セクション7 | 2 | 3 | 1/(1+2) + 1/(1+3) = **0.583** |

→ 最終順位は 2 → 6 → 7。両方の検索で良い成績のセクション2 がトップに浮上する（多数決のような働き）。

## 5. マルチインデックス・アーキテクチャと拡張性

ベクトルインデックスと BM25 インデックスがほぼ同一の API（`add_document()` / `search()`）を共有していれば、`Retriever` が両者をまとめてクエリを転送し、結果を RRF で統合できる。

重要な洞察：**異なる検索実装間で一貫した API を保つと、密結合せずに簡単に組み合わせられる**。同じインターフェースを実装すれば、キーワード検索・グラフ検索・ドメイン特化インデックスなどの新手法も Retriever が自動的に融合に組み込める。

> md-checker では、3 つの `search()` の返り値を `[(score, record), ...]` に統一することでこの疎結合を実現している。
