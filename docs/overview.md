# md-patrol 概要・要件

md-patrol を初めて読む人が最初に見る 1 枚です。「何のための道具で、何ができて、何をしないか」をここで把握できます。

## 1. md-patrol とは

ローカルにある Markdown 文書群（技術ブログ・社内文書・開発ガイドなど）を対象に、**似た記載を見つけたり、過去の記載との矛盾を指摘したりする RAG 検索エージェント**です。

新しい記事や文書を書くとき、「前にも似た説明を書いていないか」「過去の記載と食い違っていないか」を機械的にチェックすることを目的とします。

## 2. 想定ユースケース

- 技術ブログや社内文書の作成時に、過去の記事に似た説明をしていないか検索する。
- 新しく書いた内容が、過去の記載と矛盾していないかをチェックする。

## 3. 機能

| # | 機能 | 説明 |
|---|------|------|
| ① | 類似記載の検索 | 似た意味の記載箇所を検索する（ハイブリッド検索：意味＋語彙） |
| ② | 矛盾の指摘 | 取得した記載と、チェック対象の主張が矛盾していないかを AI（LLM）に判定させる |

## 4. 全体の流れ

```
[構築フェーズ（事前処理・1回）]
  resources/target_mds/ の .md → チャンク化 → ベクトル化 → vector_store.json に保存

[検索フェーズ（クエリのたび）]
  クエリ（テキスト、または Markdown ファイル 1 本）
    → （ファイル単位なら）入力をチャンク化し、チャンクごとに以下を回す
    → ベクトル検索（意味） ＋ BM25（語彙）
    → RRF で統合 → 上位 k 件の候補
    → LLM に渡して判定（機能①: 類似 / 機能②: 矛盾）
    → （ファイル単位なら）チャンクごとの結果をファイル単位のレポートに集約
```

詳細は [architecture.md](architecture.md) を参照。

## 5. 機能要件

- **① 類似記載の検索**: クエリ（自然言語、またはチェック対象 Markdown の一部）を入力すると、意味・語彙の両面で関連する既存チャンクを上位 k 件返す。
- **② 矛盾の指摘**: 取得した候補チャンクとチェック対象の主張を突き合わせ、矛盾の可能性がある箇所を指摘する（LLM による判定）。

### 5.1 入力単位（テキスト／ファイル）

機能①②はどちらも、次の 2 通りの入力単位で実行できる。

- **テキスト単位**: チェックしたい文章を直接（1 チャンク相当・最大 1200 文字）入力する。1 入力＝1 クエリ＝1 判定。
- **ファイル単位**: Markdown ファイル 1 本をまるごと入力する。構築側と同じチャンク化（[architecture.md](architecture.md) 1.1.1）でファイルを分割し、**チャンクごとに検索・判定を回して、ファイル単位のレポートに集約**する。「公開前のドラフトを過去文書と突き合わせる」「既存文書を後から再点検する」用途を想定する。
  - 入力ファイルが**まだ構築されていない新規ファイル**でも、**すでにストアに構築済みのファイル**でも入力できる。構築済みファイルを入力したときは、自分自身がヒットして無意味になるのを避けるため、検索段で**同名ファイルの候補を除外**する。

詳細は [architecture.md](architecture.md)・[design/pipeline.md](design/pipeline.md)・[design/agent.md](design/agent.md) を参照。

## 6. 非機能要件・前提・制約

| 項目 | 内容 |
|------|------|
| 対象規模 | Markdown ファイル数は **50 個未満**を想定（現状チャンク数の目安は数十〜百件規模） |
| 実行環境 | まずは**ローカルで完結**して動くこと |
| ベクトルストア | 専用 DB を使わず、**ローカル JSON（`vector_store.json`）**で簡易に持つ |
| 埋め込み・検索・判定 | 埋め込みは Voyage、矛盾判定は Claude（Anthropic API） |
| コスト | 埋め込みは構築時 1 回のみで激安。検索時のコストは候補チャンク × k 件分の入力トークン |

## 7. スコープ外（現時点）

- 大規模文書（数千ファイル）への対応。増えて遅くなったらベクトルストアを差し替える方針。
- リアルタイムの自動再構築（ファイル監視）。現状は手動で再構築する。
- Web UI。現状は CLI／スクリプトでの利用を想定。
